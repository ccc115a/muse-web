# v2.2 — typeclass 基礎（字典傳遞 + `deriving`）

版本狀態：完成。`lean/06_typeclass.lean` 雙端 SAME，全量六腳本 PASS。

## 1. 語意：執行期標籤分派

型別已擦除，靜態解析不可能——`show x` 看 `x` 的執行期標籤找實例：
nullary ctor 即符號本身、pair 取 `car`；`Nat/String/Bool/Array` 尚無實例
（調用即報清楚的錯，雙端一致）。

* registry 是純資料：`leanc` 解析期收集全部 instance，集中 emit 一個
  `(define __tcTable ...)`（後宣告居首 = last-wins，可 override），
  查询经纯函数 `__tc-find`（assoc 掃描，落空 `error` 可 catch）。
* 方法呼叫 `m a1 a2...`（`m` 為已知方法）降為
  `let t = a1 in ((extract (__tc-find __tcTable 'C (__tc-tag t))) t rest...)`，
  參數只求值一次；分派對象固定為第一參數。
* `__tc-tag`/`__tc-find`/`__reprAny`/`__reprPair` 是 Lean 寫成的內建 prelude
  （自舉：同一 parser 解析，`__` 前綴保留給它，用戶 `def` 禁用）。
  因此 `mlc` 只加了一個 `{t:'sym'}` 節點，沒有其他改動。

## 2. 表面語法

* `class Name [binder...] where` + 方法行 `m : Type`（binder/型別全跳過；
  方法順序即字典順序）。方法名與 `def`/prim/建構子 collision 皆報錯。
* `instance [name] : Class Type where` + `m [p...] := body`（續行需更深縮排）。
  `: Class Type` 必寫；Type 須先宣告；缺/重複/未知方法皆報錯。
* `deriving BEq, Repr`（inductive/structure 通用）：`BEq` 即 `equal?` 包裝；
  `Repr` 走 `__reprAny`（`nil→"[]"`、數字、字串加引號、符號、pair 遞迴、
  `Arr→"<array>"`、`procedure` 擋板）。被 derive 的 class 須先宣告；
  非標準方法名需手寫（報錯指引）。
* 新 prim `symbol->string`（雙端；`Symbol.toString` 別名）；
  別名追加 `Nat.toString`、`String.append`（`%repr-any` 需要）。
  另把 `fpvm` 的 `string-append` 對齊 wasm（`toStr` 映射；全量測試驗證）。

## 3. 不做（延後，皆有明確理由）

* 原生型別實例（要 `integer?`/`boolean?` 判別 prim）。
* 具名/遞迴實例（`%repr-any` 已覆蓋遞迴列印需求）。
* 多參數 class、優先級、overlapping 檢查（last-wins 一條規則）。

## 4. 範例與驗收

`lean/06_typeclass.lean`：`Show` 手寫實例、`BEq` 手寫 + `deriving`、
`Repr` 派生（含巢狀值）、雙參方法（`beq a b`）、override 後贏；
落空（未註冊/`Nat`）雙端同訊息。錯誤路徑（未知 class/型別/方法、
重複、缺實作、方法名衝突）皆有定位報錯。
